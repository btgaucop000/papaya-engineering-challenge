# Repository Working Agreement

## Language

- Write technical documentation, code identifiers, and commit messages in English.
- Communicate with the repository owner in Vietnamese.
- Do not write personal experiences or personal answers for the thinking questions. Those answers belong to the candidate.

## Challenge Workflow

- Read the original challenge requirements and all accepted decisions before implementing the challenge.
- Clearly distinguish among requirements from the prompt, working assumptions, and optional proposals.
- Work in scoped tasks and avoid adding features beyond the challenge requirements.
- Do not install dependencies, scaffold applications, or introduce infrastructure unless the current task explicitly requests it.

## Verification and Evidence

- Report a check as passing only after actually running it successfully.
- State clearly when checks have not been run.
- Evidence must come from an actual execution; do not invent commands, outputs, test results, or demo links.
- Do not document run or test commands as working before those commands exist and have been verified.

## Conversation Records

- Preserve raw conversation logs exactly as captured and in their original order.
- Do not edit raw logs to make the process appear cleaner or more favorable.
- Do not reconstruct or fabricate transcripts from prompts, summaries, or memory.

## Version Control

- Preserve existing content and user changes. Report conflicts instead of overwriting them.
- Do not commit or push unless the repository owner explicitly requests it.

## Challenge references

- Original brief: `challenge/docs/REQUIREMENTS.md`
- Design decisions: `challenge/docs/DECISIONS.md`

Read these files before implementing or reviewing the challenge.
